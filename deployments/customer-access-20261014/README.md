# 客户共享与隐私权限发布

这是客户管理系统的权限边界升级。财务算法、关账条件、渠道计佣算法和独立私人空间保持不变。程序只发布明确列入 `build_payload.py` 和 `release.py` 的 CRM 应用文件；测试和发布工具也需随源代码审查，不意味着 Git 中任意其它改动都可以发布。

## 老板使用路径

进入「客户中心 → 客户详情 → 共享权限」，按员工设置不可见、只读或可编辑，再分别指定基本资料、跟进、交付和素材范围。权限预览显示角色上限与生效来源，保存后由后端重新计算最终权限。

- 普通共享默认没有财务权限。需要时单独开放付款状态、客户收支或成本利润；客户财务授权不会开放公司总账。
- 现有客户负责人及销售部门继承保留，但老板设置的「不可见」或「只读」覆盖继承权限。普通管理员和财务角色不再自动获得全部客户。
- 删除历史记录、导出和调整客户负责人为独立开关，不随可编辑权限自动开启。调整负责人不等于调整渠道分润归属。
- 「老板私密备注」为独立字段，只给老板。原有普通备注和素材不会自动推断为私密；素材需明确标记共享范围。
- 只有可信 `super_admin` 老板身份可以管理共享、查看权限历史及业务修改历史。普通管理员不能自行提升为老板。

## 发布前条件

1. 根代理核对完整应用差异、攻击测试、财务/关账回归和前端构建，再冻结并提交精确源码版本。
2. 在仓库根目录运行 `python3 deployments/customer-access-20261014/build_payload.py --source <完整提交 SHA> --out <全新输出目录>`。脚本要求当前 HEAD、文件内容和构建版本完全匹配；新增路径必须经过明确的 allowlist 审核。
3. 经认证服务端预检确认原 CRM 容器 `1fc864bad248722e649c0628db163d22e98aeda38dddeeb74631ce79a3f72523`、镜像 `sha256:c5fdf50c9a26ee1811c4633a0f045e008319d486048930145c9a6d2037c3479a`，以及已固定的 Nginx、静态目录和迁移 `b3e7c1d9a614`。
4. 把独立核对哈希的 helper、manifest 和 payload 写入新的 root 所有、0700 发布目录，文件为 0600。实际服务器调用模板见 `command-example.sh`。

## 准备、启用与中断恢复

`prepare` 使用精确已验证的本地旧镜像构建候选和兼容回退镜像，在离线数据库副本执行迁移 `c4a8f2d6e714` 并测试两套服务启动。比对所有原表原列原数据，新审计表必须为空，新增默认权限必须与旧数据兼容。此阶段不切换正式 CRM。

根代理审查 `prepared.json` 后，用独立记录的 SHA256 执行 `activate`。仅 CRM 容器短暂停止，迁移在独立事务内完成；再次核对原始账目未变化后才切换服务和静态目录。私人服务不重启、不迁移。

`recover` 只用于未产生成功发布凭据的中断启用，不用于回退已验收版本。恢复从不还原数据库。若新版本已产生权限变更、老板私密备注、素材分类或审计记录，旧授权代码会被拒绝启动，避免重新暴露数据；新版本保持保护，必须通过前向修复处理。成功发布后的回退需单独审查。
