# 渠道首服务月计佣发布

本次只修改渠道计佣、渠道只读门户及账号绑定；公司利润公式、期间关账检查与私人空间源码不变。

## 操作顺序

1. 渠道管理 → 新增渠道，或者打开现有渠道。
2. 新增协议版本：首服务月比例、固定续费比例、退款观察天数及协议生效日期。
3. 客户归属 → 设置规则：选择客户/项目与渠道，填写归属生效日期和计佣起点。
   - 首服务月＋续费：填写真实首次服务日。例如 1 月 15 日开始，首服务月至 2 月 15 日之前，期间多笔服务费均用首期比例。
   - 仅续费：填写续费起算日和历史依据；未知首次服务日可留空。历史说明不会新建收款。
4. 预览影响，再确认保存。已确认、待发放、已发放记录受保护，冲突会阻止更改。
5. 扫描实收与退款 → 核对佣金 → 确认入账 → 发放登记。原关账检查仍有效。
6. 渠道卡绑定现有销售合伙人账号，或创建账号时明确选择已有渠道，避免重复档案。

季付/年付需要真实服务覆盖日期，按照已有服务收入的按天分摊口径拆分。佣金入账月继续取实际付款月，广告充值不参与佣金。

旧协议、旧归属保留历史标识。上线不根据录入日期猜测首服务月，不自动覆盖历史比例或已确认佣金；老板在页面确认新协议生效日期和计佣起点后采用新规则。

## 发布边界

- 候选镜像基于精确旧 CRM 镜像，只覆盖六个后端文件。
- 发布前先在断网数据库副本上执行迁移、原有记录比较、候选及兼容回退启动检查。
- 数据库只增加六个规则字段和渠道账号唯一索引，保留原数据；重复账号绑定会阻止迁移。
- 私人空间 API、worker、配置及数据库结构保持原样。
- 恢复只切换代码和静态入口；不恢复业务数据库覆盖期间的新记录。

实际版本、测试与上线结果以受保护服务器 receipt 及本地 outputs 证据为准。本说明本身不代表已上线。
