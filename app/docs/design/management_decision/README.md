# T24 CRM 经营决策中心——旁路扩展总体设计

日期：2026-08-03

状态：旁路基础表和只读预览已上线；分类人工审核、独立项目状态和老板经营入口已完成本地验证，等待本次发布

适用范围：T24 CRM 代运营业务，以及未来餐饮 OS、美业 OS 的经营汇总

## 1. 目标

在不改变现有客户、成交、收款、订阅、财务、工资和生命周期记录含义的前提下，为 T24 建立可逐步扩展的经营决策层，使老板能够回答：

- 哪个业务板块值得继续投入；
- 哪个行业、渠道、套餐或销售带来的客户质量更高；
- 客户为什么暂停或停止，以及真实合作周期；
- 应该招聘销售、运营还是行政；
- 餐饮 OS、美业 OS 是否达到扩大销售和研发投入的条件。

## 2. 不可破坏的边界

1. 现有表不删除、不重命名、不改变字段含义。
2. 历史金额、收款日期、订阅状态和客户状态不做批量覆盖。
3. 新统计不得把 USD、CNY 或其他币种隐式相加。
4. 投流代充值本金不是经营收入；只有确认后的投流差价属于利润。
5. 工资继续独立核算，不自动写入财务“运营支出—工资”。
6. 新指标先只读运行，不直接影响工资、佣金、奖金或员工处分。
7. 餐饮 OS、美业 OS 保留各自数据库和租户隔离；CRM 只接收必要的商家级摘要。
8. 数据迁移必须先备份、支持 dry-run、生成核对报告并可回滚。

```text

```

## 4. 两层生命周期

### 4.1 商家总生命周期

一个实体商家只保留一份主资料。商家总状态由其全部产品项目汇总：

- `prospect`：尚未发生任何付费合作；
- `active`：至少一个产品项目正常付费；
- `partial_churn`：部分产品停止，但仍有其他项目合作；
- `fully_churned`：全部产品项目均停止；
- `reactivated`：全部停止后重新产生有效付费项目。

### 4.2 产品项目生命周期

每个产品项目独立记录：

- `pending_setup`：已成交，尚未开通；
- `trial`：OS 试用期；
- `active_paid`：正常付费；
- `at_risk`：欠费、长期未跟进或服务异常；
- `paused`：双方确认暂停；
- `pending_stop`：等待管理员确认停止；
- `stopped`：已确认停止；
- `reactivated`：停止后重新开始新周期；
- `completed`：一次性项目正常交付完成，不计入订阅流失。

### 4.3 起止规则

| 业务 | 付费生命周期起点 | 风险信号 | 正式停止 |
|---|---|---|---|
| 代运营 | 第一笔有效代运营服务费，且服务已开始 | 欠费、长期未回访、交付异常、利润恶化 | 管理员确认停止日期与原因 |
| 餐饮 OS | 付费订阅生效；试用另算 | `past_due`、未完成激活、使用下降 | 取消在服务覆盖期结束后生效 |
| 美业 OS | 付费订阅生效；试用另算 | `past_due`、未完成激活、使用下降 | 取消在服务覆盖期结束后生效 |
| 一次性项目 | 项目首款且已开始交付 | 逾期、范围变更、验收阻塞 | 正常完成或取消，不计订阅 churn |

纯投流充值不得触发代运营生命周期；套餐到期、自动扣款失败或 `past_due` 只产生风险信号，不自动判定客户流失。

## 5. 四个独立维度

以下字段必须独立保存，禁止互相推导：

- 业务板块：代运营、餐饮 OS、美业 OS、一次性项目；
- 商家行业：餐饮、美业、按摩、医美及其他；
- 收费周期：月付、季付、年付、一次性；
- 收款方式：Stripe 自动扣款、银行转账、支票、Zelle 及其他。

银行转账和支票也可能是周期性订阅；Stripe 只是收款方式，不等于产品或收费周期。

## 6. OS 系统接入边界

CRM 只保存：

- `external_system`：`restaurant_os` 或 `beauty_os`；
- `external_merchant_id`、`external_store_id`；
- 套餐、试用/付费/欠费/取消状态；
- 激活里程碑和最近活跃日期；
- MRR/ARR 摘要、支持工时摘要；
- 同步时间、来源版本和幂等事件 ID。

CRM 不直接复制订单明细、消费者资料、预约详情、银行卡数据或商家员工隐私。餐饮 OS 的所有业务查询继续以 `store_id` 作为租户边界。

## 7. 交付顺序

1. 设计基线：本目录文档评审通过。
2. 旁路基础表：只新增表、索引、权限和审计字段。
3. 代运营影子回填：生成建议关联，不写回旧表。
4. 影子指标：新旧生命周期并行计算，形成差异报告。
5. 只读老板看板：先展示数据质量、客户风险和板块指标。
6. 团队记分卡：只用于管理观察，不接工资。
7. OS 受控试点同步：先测试商家，再开放真实商家。
8. 决策信号：积累 3–6 个月稳定数据后启用。
